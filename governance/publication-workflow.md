On November 6, 2026 there was [a Working Group Decision to adopt the following publication process](https://lists.w3.org/Archives/Public/public-socialweb/2026Nov/0004.html) for Drafts we publish in the [W3C Recommendation Track](https://www.w3.org/policies/process/#rec-track).

---

All proposed changes to a WD will be opened as a PR in the appropriate repo for the WD. 

1. A PR opens with a `needs-class` tag, and a 4-week timer starts.  
   1. An exception is that Class 1 changes may be directly labelled  `class-1` and may be merged at any time by a Chair or W3C Team member  
2. Each WG meeting has reserved time to discuss  `needs-class` issues where we assign a Correction Class. When the Class is agreed upon, the Chair tags it with the agreed Class and the minutes email highlights the PRs and their newly assigned Class. Objections to a classification are raised on the PR, like any other objection.  
3. Based on its new Correction Class, a window for comment opens on the issue.

| Correction Class | Comment window | Non-author \+1s |
| :---- | :---- | :---- |
| 1, 2 | 7 days | 1 |
| 3, 4 | 14 days | 2 |

4. **PR is merged** when the window ends with no unresolved objection and the required \+1s.  
5. An objection from a WG member raised in the PR pauses the window**..** Once resolved, a fresh 7-day window starts, with the Class's usual approval count.  
6. A **PR is closed** as "no resolution" if the 4-week timer runs out with an unresolved objection or too few approvals. (If a 7-day timer post-resolution is still going at this point, we extend the 4-week deadline to accommodate that timer and merge at the end of the window assuming no new objections.)
